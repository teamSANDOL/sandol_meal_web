# Sandol Meal Web

`sandol_meal_web`는 산돌이 학식 서비스의 관리자/식당 주인용 기능성 웹 UI를 제공하는 FastAPI 기반 BFF 서비스입니다.

## 목표

- Keycloak 로그인 세션 관리
- `sandol_meal_service` API를 서버 사이드에서 호출
- 디자인보다 기능 동작을 우선한 서버 렌더링 HTML 제공

## 실행

```bash
uv sync
uv run uvicorn main:app --host 0.0.0.0 --port 5800 --reload
```

## 프론트엔드 자산

UI는 서버 렌더링 HTML 위에 정적 자산으로 구성되어 있습니다.

- CSS/JS/이미지 위치: `app/static/`
- FastAPI 정적 경로: `/meal-web/static/...`
- 별도 Node.js/Next.js 실행은 필요하지 않습니다.

디자인은 **산돌 디자인 가이드 v0.1** 기반이며, 모든 토큰은
`app/static/css/sandol-ops.css`의 `:root` CSS 변수 하나로 관리합니다.
본문 폰트 Pretendard는 CDN에서 로드합니다(오프라인 배포 시 woff를
`static/fonts/`로 내려받아 URL만 교체). 카카오 옐로(`--sd-yellow`)는
화면당 주요 CTA 1개에만 사용합니다.

## 현재 상태

- Keycloak 인증/세션 기반 서버 렌더링 UI 제공
- 식당주: 등록 요청, 내 식당·매니저 관리, **식단 등록/수정/삭제**
- 관리자: 운영 대시보드, 등록 요청 검토, 식당·매니저·식단 관리

## 관리자/식당 주인 사용 가이드

외부 접속 기준 기본 경로는 `/meal-web` 입니다.

### 공통 흐름

1. `/meal-web/`에 접속합니다. 랜딩에는 관리자 진입 경로가 노출되지 않습니다.
2. `로그인하고 시작하기`를 눌러 Keycloak 로그인 페이지로 이동합니다.
3. 로그인이 끝나면 권한에 맞는 화면으로 자동 이동합니다.
   관리자는 `대시보드(/admin)`, 그 외에는 `내 식당(/owner/restaurants)`입니다.
4. 화면 상단의 `로그아웃` 버튼으로 로그아웃할 수 있습니다.

### 식당 주인(owner) 사용 흐름

1. `내 식당`에서 소유·매니저로 참여 중인 식당을 카드로 확인합니다.
   카드에는 오늘 식단 등록 여부와 대기 중인 매니저 신청 수가 표시됩니다.
2. `식단 관리`에서 오늘의 끼니별 등록 현황(아침·점심·저녁)을 확인하고,
   비어 있는 끼니는 `지금 올리기`로 바로 등록합니다.
3. 식단 등록·수정 화면에서는 메뉴를 칩 단위로 추가·삭제하며, 제출은 기존과 같이
   줄바꿈으로 구분된 `menu` 값으로 전송됩니다.
4. 식단 목록에서 `수정` 또는 `삭제`로 이미 올린 기록을 관리합니다.
5. `등록 요청`에서 제출한 요청을 상태 탭(대기·승인·거절)으로 확인하고,
   상세 화면에서 진행 상황·거절 사유를 봅니다. 삭제는 확인 체크 후 가능합니다.
6. 식당 상세 화면의 `매니저 신청` 탭에서 카카오봇·웹으로 접수된 신청을 승인합니다.
7. 다른 식당에서 일한다면 `내 식당` 하단에서 매니저 신청을 보낼 수 있습니다.

### 관리자(admin) 사용 흐름

1. `대시보드`에서 검토 대기 요청 수, 등록 식당 수, 오늘 식단 등록 현황과
   식당별 최신 식단을 한 화면에서 확인합니다. `식단 강제 동기화`도 여기서 실행합니다.
2. `등록 요청`에서 상태 탭과 검색(식당명·신청자)으로 요청을 좁힌 뒤 상세로 이동합니다.
3. 상세 화면에서 정보를 검토해 `승인`하거나, 사유를 입력해 `거부`합니다.
4. `식당`에서 식당명·유형·교내외 필터로 목록을 좁히고, 상세 화면의
   `정보 · 관리` / `매니저` / `매니저 신청` 탭으로 이동합니다.
5. 식당 상세에서 소유자 변경, 매니저 등록·해제, 매니저 신청 승인, 식당 삭제를 처리합니다.
6. `식단`에서 식당명·끼니·제공일 범위로 필터링하고, 20건씩 페이징하여
   등록·수정·삭제합니다.

식당 소유자 변경은 관리자에게만 허용됩니다. 일반 사용자의 소유권 이전은 이전 신청과
신규 소유자의 승인 절차를 별도로 거쳐야 하며, 현재 관리자 수정 API를 직접 사용할 수 없습니다.

### 참고

- 비로그인 사용자가 보호된 페이지에 접근하면 로그인 페이지로 이동합니다.
- 관리자 페이지는 `global_admin` 또는 `meal_admin` 권한이 필요합니다.
- 모든 상태 변경 요청(로그아웃 포함)은 CSRF 보호가 적용됩니다.

### meal-service 확장이 필요한 미완성 기능

다음 화면 요소는 UI가 준비되어 있으나 `sandol_meal_service` 확장 전까지 동작하지 않습니다.

| 기능 | 현재 동작 | 필요한 백엔드 작업 |
| --- | --- | --- |
| 매니저 신청 **거절** | 안내 메시지 표시 | `POST /restaurants/{id}/manager-requests/{rid}/rejection` 추가 |
| 식당주 본인 식당 정보 수정 | 버튼 미노출(`can_edit=False`) | `PATCH /restaurants/{id}` owner 허용 |
| 식당주의 매니저 직접 등록·해제 | meal-service 403 메시지 표시 | `POST`/`DELETE .../managers` owner 허용 |
